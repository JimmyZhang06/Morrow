# Morrow 产品设计：从经历到理解

版本：设计稿 v1.0
日期：2026-09-10
状态：下一阶段产品设计，尚未实现；不代表当前发行版功能承诺。
适用范围：Windows 本地桌面版，个人使用，自行配置在线模型 API。

## 1. 产品要解决什么问题

人们会记下困扰、感受和决定，但记录之后，经常仍然不知道这件事为什么重要、下一次能怎样应对。通用 AI 可以提供解释，却容易复述原话、套用人格标签，或忘记用户之前已经纠正过的判断。

Morrow 帮助用户把在意的经历说清楚，从中形成由自己认可、可以继续修改的理解，并在后续生活中验证它。

**产品主线：遇到一件在意的事 → 把它说清楚 → 获得一点新的理解 → 带着理解生活 → 用新经历更新理解。**

对外表达建议：**记录经历，慢慢看懂自己。**

用户不必每天记录，不必每次接受分析，也不必把每一次理解变成行动。一次使用能够安静地结束在“已经记下了”或“这件事我更清楚了一点”。

## 2. 用户、场景与价值

首轮试用优先覆盖愿意记录、遇到反复困扰、希望得到具体帮助的成年人。以工作中的行动阻力和沟通经历作为评测场景，产品不限制用户只能记录工作。

| 场景 | 用户带来的内容 | 本次使用希望得到什么 |
| --- | --- | --- |
| 想留下经历 | 今天发生了一件值得记住的事 | 快速保存，之后能找回 |
| 一件事想不通 | 我为什么一直为这件事难受 | 梳理细节，看见可能忽略的区别 |
| 相似问题又发生 | 我好像又重复了之前的选择 | 找到相关经历，比较条件，而非重复听建议 |
| 为下一次准备 | 我想换一种方式表达或开始 | 一次简短排练或一个具体尝试 |
| 回看一段生活 | 最近我有什么变化 | 看见经历与理解的变化，整理个人叙述 |

核心价值通过三个问题验证：用户是否更清楚发生了什么；是否产生了有依据的新理解；之后是否能继续利用或修正这份理解。

## 3. 产品结构：一条日常主线，四个导航入口

| 一级入口 | 主要内容 | 主要动作 |
| --- | --- | --- |
| 首页 | 快速记录、最近探索、值得回访的内容 | 记录一件事、继续探索 |
| 经历 | 时间顺序的记录、搜索、标签筛选 | 找到并打开一段经历 |
| 我的理解 | 待确认发现、已保存认识、变化记录 | 确认、修改、比较、撤回 |
| 人生回顾 | 人生线、阶段回顾、回忆录 | 选择时间范围、整理主题、编辑文稿 |

设置位于侧栏底部，保留模型配置、隐私、备份恢复和显示设置。行动在对应探索中管理，首页提供回访入口；“我的理解”提供关联尝试筛选，避免离开首页后无法找回。现有日历导出保留在行动详情。

“探索”是围绕一件事展开的工作页面，可以从任一入口打开，不再增加一级导航。视角切换、历史比较、追问和排练是这个页面中的工具。

## 4. 完整用户旅程

### 4.1 第一次打开

空白首页显示“有什么想记下来的？”，用户无需配置 AI 即可记录。保存后明确提示“已保存在本机”，提供次要操作“和我一起看看”。

尚未配置模型时，点击探索说明在线分析需要发送所选材料，提供“配置模型”和“先只记录”。不使用看似真实的预置日记填充页面。若提供示例，必须作为明确标记的独立演示，不进入个人记录、搜索或 AI 历史。

### 4.2 记录一件事

首页允许自由输入，标题可选，支持草稿。保存和 AI 分析是两个独立动作，不因保存记录自动发起在线请求。编辑、删除和冲突保护继续保留。

保存后只有一个主要探索入口“和我一起看看”，不同时要求用户选择分析类型、认知类别或工作流。

### 4.3 把事情看清楚

进入探索页后，原记录始终可以查看。AI 根据材料选择一个最有价值的下一步：澄清细节、提出一个暂定解释、比较相关经历，或说明目前没有额外发现。

默认最多展示一个追问、一个主要发现；不强迫每次填满固定分析模板。用户可以跳过问题、直接写补充，或者结束探索。

用户新增的叙述保存为带时间的补充材料；AI 文本作为生成内容单独保存，不能混入用户原话。

### 4.4 留下一点理解

用户认可某个发现后，可以改写为自己的表达，再保存到“我的理解”。允许“部分符合”，补充适用条件；允许“暂时不确定”，保留为候选；允许拒绝并可选填写原因。

确认代表用户认可当前表述，不代表它成为客观事实。材料或认识发生变化后，重新标记需要复核，不静默改写用户已经保存的内容。

### 4.5 可选：为下一次做准备

从已保存理解或当前探索进入“试一件小事”或“练习怎么说”。每次建议说明它与当前经历的关系，用户自行编辑、接受或放弃。

回访除了“完成”，还允许“没做”“做了但没帮助”“情况变了”。未完成不会被解释为意志薄弱，也不产生逾期惩罚。

### 4.6 新经历回来更新理解

在用户主动开展下一次在线探索时，系统可以检索获准范围内的相关历史，并显示“这可能和之前的一件事有关”。只有保存记录时不自动上传进行关联分析。

用户选择并排比较，标记重要差异，再决定保持原认识、补充条件或修订表述。修改保留版本及原因。

## 5. 一次探索的具体示例

以下是虚构设计示例，不用于预置个人数据。

原记录：“今天会上我的建议被否了，我没再说话，晚上一直不舒服。”

| 步骤 | 页面内容与动作 | 产生的结果 |
| --- | --- | --- |
| 打开 | 原文居中，操作“和我一起看看” | 创建围绕该记录的探索 |
| 澄清 | “你愿意补充一下，对方当时怎么说的吗？” | 用户补充具体表达；也可跳过 |
| 切换 | 查看“发生的事”和“当时的想法” | 分开用户记述的事件与解释 |
| 比较 | 经用户选择，打开另一段建议未被采纳的经历 | 两段原文并列，不编造历史 |
| 判断 | 用户指出“上次对方认真解释了原因” | 差异由用户决定，而非自动归因 |
| 保存 | “我在意自己的准备是否被认真对待” | 保存认识，关联两段依据 |
| 准备 | “下次先问对方最担心哪个部分” | 可选小尝试或短排练 |
| 回访 | 用户补充尝试后的实际情况 | 保持或修订认识，留下原因 |

任何一步都可以退出，重新打开时继续到最后保存的位置。直接查看分析的需求仍被支持，用户无需逐项完成所有交互。

## 6. 页面与交互规格

### 6.1 首页：开始和继续

顶部是记录输入区。其下最多三条继续项，按最近主动参与、用户设定回访时间、新材料关联的顺序展示。每项写清缘由，例如“上次你想补充这段经历”，而不是“AI 有新洞察”。

支持隐藏、稍后处理和关闭回访。没有待处理内容时保持简洁，不制造每日任务。首版不提供连续签到、人生评分和未完成红点。

### 6.2 探索页：围绕原文逐层展开

宽屏布局为左侧简洁导航、中央探索内容、右侧按需打开的材料面板。材料面板默认收起，窄窗口改为抽屉；原文和探索结果之间提供明确返回位置。

顶部包含经历标题、保存状态、当前模型及“本次使用的材料”。主体先呈现原文和当前一步，补充内容顺序保留。底部提供输入补充、保存理解和结束探索，不堆叠所有工具。

选中文字后显示“展开这句话”，键盘选中与按钮操作同样可用。展开可以补充当时想法、查看相关材料或向 AI 提问。不得仅依赖悬停、颜色或拖拽完成操作。

### 6.3 视角切换：同一材料，不同组织方式

| 视角 | 展示内容 | 约束 |
| --- | --- | --- |
| 发生的事 | 用户记述的言语、行为、顺序 | 这是用户的记述，不宣称已验证客观事实 |
| 当时的我 | 当时的感受与解释 | 未提供的信息留空或询问，不补写心理活动 |
| 今天的我 | 用户现在的重新理解 | 与当时的材料分开，注明补充时间 |
| 另一种解释 | 最多两个有材料关联的替代解释 | 明确为推测，不默认积极化或替他人辩解 |

切换通过标签按钮完成，保持阅读位置。默认不播放复杂动画；减少动态效果设置下即时切换。

### 6.4 经历比较：找出有意义的差异

两段经历并排显示日期、原文和用户补充。窄屏上下排列。可以由用户主动选取，也可以接受 AI 推荐。AI 推荐需说明关联原因。

AI 标注的差异是候选，用户可选择“这点重要”“不相关”或添加自己的差异。只有用户认可的差异才可用于保存新的理解。没有合适历史时，允许单独探索或请用户补充回忆，不伪造第二个场景。

### 6.5 我的理解：可修改的个人认识

默认展示用户保存的认识及其适用条件，待确认内容作为同页筛选，不作为强制清空的收件任务。详情包含相关经历、补充条件、相反材料、版本变化和关联尝试。

主要操作为“修改表述”“补充条件”“暂时搁置”“撤回”。候选保留确认、部分符合、拒绝和暂缓。合并两条认识时展示合并预览并由用户保存，旧版本仍可查看。

### 6.6 行动与排练：带回现实

小尝试包含要做什么、为什么值得试、何时回看。用户可选择只保存，不设置时间。避免所有建议都变成“写十分钟”或“拆分任务”。

排练由用户设定情境和想练习的表达，开始前说明角色是模拟。默认三轮内可结束，支持暂停、重说、调整情境。结束时保留用户选择的表达与尚未解决的困难；模拟回复不进入真实经历依据。

### 6.7 人生回顾：长期积累的阅读方式

人生线保留事件时间线，增加“理解变化”显示选项。点击任一变化可回到来源和修订原因。AI 推荐的阶段主题仍需用户确认。

回忆录继续以单章草稿为交付单位，逐步加入材料选择、主题调整、段落来源和用户编辑。生成文稿不能反向当作新的经历证据；原始材料删除或修改后，关联段落标记需要复核。

### 6.8 可读性

延续整体字体放大的要求：主要界面文字默认 16px，阅读正文 17–18px，辅助文字不低于 14px，正文行高约 1.6。主要点击目标至少 40px。

支持键盘焦点、明确按钮名称和文本状态。验证 Windows 100%、150%、200% 显示缩放，以及 980px 宽窗口；比较视图和材料面板应响应布局，不靠缩小字体容纳内容。

## 7. AI 如何工作

### 7.1 从“一句洞察”升级为按需探索

每次请求先判断当前需要什么：直接回答、澄清、比较、提出解释、更新理解，或暂不产生发现。一个追问应该能帮助区分解释；若答案不会改变下一步，就不必询问。

分析应带来新的区分、相关材料或可检验的解释。仅将“我想自由安排工作”改写成“你重视自主”不能作为主要发现。无增量时可明确说“目前还没有比你的描述更进一步的发现”，并允许结束。

对用户直接提出的问题先作回应，不把所有输入强行转成探索模板。用户需要安慰时可以简短回应，但不要据此制造稳定人格判断。

### 7.2 上下文选择

上下文以本次记录及补充为中心，加入少量相关经历、用户认可的认识、适用条件和相关纠正。检索同时考虑相似经历和可能的反例，不能只找支持既有判断的材料。

首版采用明确授权范围与可查看的材料列表：仅当前经历、用户选定经历、允许检索个人历史。扩大范围或改用新供应商时重新展示相应数据使用说明。展示引用并不等于已经获得上传授权。

用户拒绝的认识不再作为认可结论使用。拒绝原因可以帮助避免重复错误，但只在相关情境使用，不能转化为全局人格标签。

### 7.3 生成结果与校验

内部结果按需要包含：回应、主要发现、证据引用、替代解释、一个追问、相关经历建议和下一步。没有依据的字段允许缺省，界面不展示空模板。

引用必须指向实际来源及版本并通过校验。重复性可以先采用规则与相似度检查，再根据质量评测决定是否增加模型审查，避免每步多次调用。不得用伪精确的概率包装心理推断。

新材料只生成修订建议，不能直接覆盖用户确认的认识。模型切换不会清空探索；记录、纠正和版本属于本地产品数据，不依赖某家模型的聊天记忆。

### 7.4 等待与失败

| 状态 | 用户看到什么 | 可做什么 |
| --- | --- | --- |
| 未配置模型 | 记录已保存，在线探索需要配置模型 | 前往设置或继续记录 |
| 正在生成 | 可见等待状态，原文继续可读 | 取消、离开后回来 |
| 超时或供应商错误 | 请求未完成，记录和补充仍在 | 手动重试或切换模型 |
| 引用校验失败 | 本次分析未能可靠关联原文 | 重试，不显示伪造的有效引用 |
| 无相关历史 | 当前没有合适的比较材料 | 单独探索或主动补充 |
| 来源被编辑或删除 | 相关理解需要复核 | 查看变更、修改或撤回 |

不自动无限重试收费请求。模型切换时旧任务不能悄悄改送新供应商。异步结果只附加到其所属探索，不覆盖用户后续编辑；迟到结果需要标明依据的是较早材料。

## 8. 数据关系与信任边界

| 对象 | 保存什么 | 与其他对象的关系 |
| --- | --- | --- |
| 经历 | 用户记录、补充及版本 | 是探索和引用的来源 |
| 探索 | 围绕某件事的进度、回复与材料选择 | 连接经历、候选理解和尝试 |
| 理解 | 用户保存的表述、条件、状态及版本 | 关联支持材料、反例和修订原因 |
| 尝试 | 用户接受的行动或排练及反馈 | 关联探索；真实反馈可作为补充材料 |
| 回顾文稿 | 主题、章节、编辑与引用 | 消费已有材料，不成为原始事实来源 |

保留现有 Source → Derived → Evidence → Verdict 的设计基础。新对象是产品领域设计，实施前需要映射已有数据结构，不能仅凭本文声称迁移完成。

删除来源后，后续检索及在线上下文排除它；依赖该材料的认识和文稿失去相应依据并标记复核，不能继续通过旧摘要泄露原文。备份及旧版本目录的副本边界需在删除说明中如实展示。

应用和数据继续在 Windows 本机，在线 AI 使用用户配置的 API。发往模型的内容不等于本地存储，密钥保护与现有备份恢复能力继续保留。

安装包必须不含开发记录、个人历史、测试配置和密钥。当前发行版采用按版本隔离、首次空白的策略；本文不改变该行为。正常升级迁移个人数据有利于长期体验，后续应单独设计和确认，现阶段继续通过用户主动恢复备份迁移。

## 9. 现有功能如何保留与升级

| 已有能力 | 本轮处理 | 最终入口 |
| --- | --- | --- |
| 记录、草稿、编辑删除、分页与冲突保护 | 保留，增加关联探索 | 首页、经历 |
| AI 候选认识及原话引用 | 保留，增加追问、替代解释和无发现结果 | 探索页 |
| 确认、纠正、拒绝、暂缓 | 保留，增加条件与版本呈现 | 我的理解 |
| 小行动及完成撤销 | 保留，增加关联目的与结果回访 | 探索详情、首页回访 |
| 日历文件导出 | 保留现有显式导出方式 | 行动详情 |
| 人生主线 | 保留，增加认识变化与来源回看 | 人生回顾 |
| 回忆录单章草稿 | 保留，逐步增加材料与叙述编辑 | 人生回顾 |
| 多模型与独立密钥 | 保留，保障切换后探索可继续 | 设置 |
| 本地运行、备份恢复、干净发行 | 保留 | 设置与发布流程 |

导航调整不能造成旧数据不可达。候选、行动、文稿都应有明确的新入口；历史内容不因新分析格式而自动重算或产生费用。

## 10. 实施范围和验收

### 第一阶段：把日常主线连顺

交付：首页与四入口导航、探索页面、原文与补充材料、改进的 AI 分析、候选保存到我的理解、离开后继续。其他现有功能迁入对应位置，保留访问和行为。

暂不加入场景排练、自动跨历史比较和复杂认识合并，避免一次改动过大。第一阶段结束时，用户能完整体验“记录 → 探索 → 保存理解 → 再次打开”。

### 第二阶段：做出核心交互差异

交付：句子展开、视角切换、用户选取两段经历比较、授权历史检索、条件修订、认识版本、行动结果回流。先做用户主动比较，再增加 AI 推荐。

本阶段验收重点是用户能否通过比较指出一个重要差异，并将其保存或用于修订；不以点击次数和动画丰富度判断创新效果。

### 第三阶段：加强准备与长期回顾

交付：简短场景排练、人生线的理解变化视图、回忆录材料选择与来源编辑。根据前两阶段反馈决定是否增加持续问题专题，首版不提前加入新的一级入口。

### 发布与质量门槛

- 无模型时，记录、编辑、搜索和已有内容阅读仍可用。
- 空白用户能完成第一条记录；探索中途退出后可继续，无重复生成和丢失补充。
- 每个展示的引用都能定位到正确来源；推测、用户补充和模拟对话明确分开。
- 用户修正后，相关下一次探索能使用修正；旧认识不被静默覆盖。
- 无合适历史、无新发现、供应商错误都有可结束的路径。
- 现有记录、候选、行动和文稿在新导航下全部可达。
- 字体、缩放和键盘操作通过真实桌面验证；发布包通过无个人数据与密钥检查。

## 11. 如何验证“更有用”与“交互更好”

先制作约 20 组去标识或人工构造材料，覆盖信息不足、重复抱怨、反例、用户否定旧结论、来源变更和无历史场景。对比当前版与新版分析，人工检查依据、增量和是否套话。此数量是首轮工作量建议，不是统计有效性承诺。

邀请约 5–8 位试用者完成首次记录、展开经历、比较经历和修订认识。观察他们能否理解下一步，以及何处需要解释。对比同一任务的普通对话方式与探索页面，不把新界面必然更好作为前提。

每次探索结束可选反馈：“只是复述”“有新的理解”“不符合我的情况”；补充询问哪里有帮助。隔一段时间回访认识是否仍有用、是否被修正。记录这些反馈时默认保存在本机，研究分享采用用户主动导出，不上传日记内容作为遥测。

首轮发布需清除阻断完成任务的问题和关键误导性输出。分析质量与交互偏好未达到一致结论时，保留简单阅读路径，继续调整；不以更多生成、更长停留或更多确认作为成功替代指标。

## 12. 本版设计的边界

本设计保留原有记录、理解、行动、人生线和回忆录，统一其进入与返回路径。新增能力围绕原文展开，不要求用户学习一张复杂的个人知识图谱。

首要交付不是更多页面，而是让用户完成一次清楚、可继续的探索：**我记下了一件事，看到了一个有依据的新角度，并且知道这份理解之后可以在哪里继续。**
