# AI 前端呈现收敛（2026-08-25）

## 本轮结论

前端不把 AI 呈现为聊天对象、人格诊断或自动结论，而把它限制为一条可核对的阅读路径：

`你的原话 → 一个可能的发现 → 展开原话 → 你的判断 → 一次可撤销的小尝试`

## 已落地

- 记录详情只提供低压力入口“发现一个线索”，并明确最终由用户判断。
- 认识页改为单列阅读流，使用“待判断 / 已认可 / 未采用”，降低任务列表感。
- 认识详情将候选、原话证据与用户裁定分层；技术 ID、供应商和后端术语不进入日常界面。
- 证据失效时 fail closed：标记“依据待更新”，禁用确认、纠正、驳回和暂缓操作。
- 用户认可或纠正后才能创建“尝试”；尝试支持接受、完成和撤销，不使用逾期、失败或连续打卡反馈。
- 运行能力清单折叠到设置页“运行诊断”，主界面只显示“已安全连接 / 认识整理可用”。
- 新候选提示词要求中文产品中的候选直接对用户说“你可能……”，避免“用户……”和报告式语气；提示词版本升级为 `candidate-insight-v3`。

## 真实验证

使用一条虚拟笔记通过真实 StepFun provider 完成浏览器闭环：保存并同步、生成结构化候选、展开真实原文、确认候选、创建尝试、接受、完成和撤销。生成结果采用暂定第二人称表达，证据摘录与 Source 原文一致。

## 当前边界与遗留问题

1. 当前候选生成仍是单条记录整理，不代表跨时间、跨记录的人生模式发现；界面已避免声称“多条记录得出”。
2. 旧版 v1/v2 候选是不可静默改写的历史产物，仍可能保留第三人称或旧文案；v3 只影响新生成结果。
3. Vault consent/source snapshot 变化后，旧候选证据会按后端策略失效。前端已禁止无依据裁定，但仍需要后续提供明确的“重新整理”入口。
4. 小尝试目前由受控领域模板生成，尚不是第二条模型链；这是有意保持的闭环范围。
5. 暂不扩展回忆录、人生主线、外部 Todo 或 Calendar。
