# 认识页：连续改判与版本逻辑修复

## 问题与新的交互规则

此前只补了“调整判断”按钮，没有覆盖连续操作，导致用户仍可能无法更新：

1. 不符合、暂缓、撤回都会推进 review revision，但前端只在确认和纠正后重读详情。下一次请求仍使用旧详情 ETag，冲突后也只刷新列表，因而重复冲突。
2. 后端把“内容来自用户纠正”固定映射为“当前判断是已纠正”，后续认可、拒绝或暂缓会被盖住。
3. 调整入口折叠，修改框为空，缺少判断历史；依据缺失还会阻止用户修改自己的表述。

本轮把三个概念分开：

| 概念 | 行为 |
| --- | --- |
| 文字版本 | 修改表述生成新版本，保留旧版；编辑框预填当前内容。 |
| 当前判断 | 认可、不符合、暂缓可以反复更新，以最新判断事件为准，不改写正文。 |
| 撤回 | 停止使用该条认识，是终止操作；页面提示与“不符合”有区别，不提供无效的继续改判按钮。 |

每次保存后都同步刷新详情、列表与 ETag，刷新完成前禁用重复提交。遇到版本冲突重新读取该条详情，保留用户修改草稿，不自动覆盖其他更新。

调整判断直接展示；增加按时间倒序的判断记录。原文依据暂不可用时，仍允许修改表述、拒绝或暂缓，但不允许直接确认无依据的旧解释。只有当前认可且实际处于 active 状态的认识才展示生成尝试的入口。
