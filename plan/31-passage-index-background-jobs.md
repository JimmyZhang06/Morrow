# 日记分段索引与后台补建实施记录

日期：2026-09-11。接续 [第一批记录](30-memory-implementation-progress.md) 和 [技术方案](29-long-term-memory-chat-technical-spec.md)。

## 已实现

1. 日记采用最大 600 个 Unicode 字符、80 字符重叠的确定性分段，优先在句末换段。分段保留原文起止位置、摘要哈希和关键词，原始 SourceRevision/SourceFragment 不变。中文、换行、emoji 和组合字符原文不被重写。
2. 搜索命中后验证并解密原文，对段落重新评分，返回更相关的原文摘录及段落位置。新索引版本为 `morrow-cjk-passages-v2`；旧版本索引需要用户主动补建，不自动把旧结构当成已升级。
3. 新增持久后台补建任务，用户点击一次即可启动。每批最多 25 条；已检查数量、索引数量和 UUID 游标与索引在同一事务提交。批次失败回滚，中断前已提交的进度可继续使用。
4. 后台任务不依赖记录页持续打开；桌面离开后继续运行，重新打开页面从 API 读取状态。取消保留已建索引，关闭 SEARCH 则取消任务并清除索引载荷。失败显示可重新开始，不无限自动重试错误批次。
5. 任务执行重新验证成员身份版本、SEARCH、源级 opt-out、当前来源及敏感级别；不调用在线模型。跨空间的任务 ID 不能驱动另一空间的任务。

## 存储和接口

新增迁移 `12ab34cd56ef`，从 `c9a7e3f1b204` 升级：

- `search_projection.lexical_passages`：可删除的 JSON 派生分段，不存正文。沿用投影的空间 FK、来源关系、权限和 RLS；新 CHECK 禁止已删、无索引权限和高度敏感投影保留分段。撤权与数据库来源隔离函数一并清除该字段。
- `diary_index_job`：保存任务状态、请求者/成员版本、处理游标、计数和时间。只有技术数据，没有日记标题、原文、查询、模型密钥。
- `life_coach_private.next_diary_index_job()`：固定作用域的派发函数，只返回待处理任务的技术身份；业务读取仍经授权事务。PUBLIC 无执行权限，桌面既有受限角色可以执行。已删除空间、停用身份和失效成员不会派发。

分段暂时存于现有投影 JSON，没有另建独立 chunk 表。这样继承现有来源删除路径，减少重复的原文身份；检索读取仍回源验证，不信任派生索引内容。未来数据库侧分段排名和性能优化可以再拆表迁移。

| 方法 | 新路径 | 行为 |
| --- | --- | --- |
| POST | `/v1/local-search/index-job` | 返回 202；同空间已有排队任务时返回该任务，避免重复点击创建多份 |
| GET | `/v1/local-search/index-job` | 最新任务或 null，含 id/state/processed/indexed |
| POST | `/v1/local-search/index-job/{id}/cancel` | 取消本空间未完成任务，返回 204 |

保留第一批 `/query`、`/rebuild` 接口。桌面根据 `local_search_background` 能力标记采用后台补建；未提供后台能力的后端沿用手动批次。

## 事务与恢复

每批先锁 Vault，再锁任务，保持与授权、编辑和取消的锁顺序一致。分段处理不跨事务持有执行 lease；同一批的索引和游标一起提交，多个 worker 依靠事务锁串行推进。没有外部供应商副作用，因此重跑一个未提交的本地批次不会重复收费。

任务按 SourceFragment UUID 翻页，覆盖任务开始前已存在的日记。保存/编辑继续建立当前索引，因此处理中出现的新修订不依赖旧游标才能得到索引。已删除和被排除来源不会再进入批次。

关闭搜索的取消放在公共索引撤回服务中，避免只靠桌面接口阻止任务；再次开启不会自动复活已取消任务。备份继续包含数据库新字段和任务表；在线 AI 的恢复规则不改变。

迁移安装权限时根据数据库实际存在的表和字段处理，避免旧迁移读取最新模型注册表后尝试给未来表加权限。新迁移已做真实 PostgreSQL 升降级演练。

## 验证结果

- 完整回归：1094 passed、2 skipped；一条既有 Starlette/httpx 弃用提示。
- 新增分段覆盖、确定性、句边界、中文/emoji 原文偏移、长日记相关摘录和撤权清空测试。
- 后台批次测试：数据库提交后重新加载任务继续处理，批次异常同时回滚进度和索引，取消、撤权和跨空间 ID 隔离。
- API 测试：未开启搜索拒绝创建任务，重复请求返回同一任务，取消状态可读取。
- 真实内置 PostgreSQL：迁移演练、非 owner RLS、独立后台补建、授权、修订、删除、加密备份/恢复及重启通过。
- Python mypy 与 Ruff、前端 TypeScript/Vite 构建通过。
- 实际打包桌面程序：开启搜索、后台补建完成及计数、搜索、打开未加载历史原文、关闭搜索通过；150% 紧凑窗口无横向溢出。首次运行的测试等待内置服务就绪后再验证数据库同步。
- 打包后端独立完成 CRUD、加密备份、恢复与重启验证；实际桌面新资料空间的记录、认识、行动、草稿与模型密钥均为空，AI 默认关闭。
- 全部使用合成记录与独立测试目录，没有向真实模型供应商发送请求。

## 仍未实现的内容

本批继续推进 P1，没有将 P2/P3 宣称完成：

- 查询仍只扫描最近 1000 条当前片段，并明确显示截断；后台补建能向前继续处理更早日记，但索引覆盖量不等于当前查询覆盖量。
- 保存时的单条索引仍在写入事务内完成；后台任务用于历史补建，没有改成每次保存都入队。
- 分段位置采用 Python Unicode 字符索引；前端若增加逐字高亮，应转换 UTF-16 位置。
- 词法检索尚无语义理解、独立时间推理、反例检索和 5000 chunk 性能达标结论。
- AI 对话、会话持久化、上下文 manifest、生成引用、授权模型任务及可纠正长期记忆仍待实施。
- 此次生成开发验证用程序，没有发布新版本安装器或推送 GitHub。
