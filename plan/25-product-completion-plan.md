# Morrow / Vistora 产品完成计划

日期：2026-09-01

状态：执行基线

目标：把当前“高级工程 MVP”收敛成普通用户可安装、可完成核心闭环、可安全运营的产品。

## 1. 完成目标

本计划只围绕一条黄金路径推进：

```text
安装并创建私人空间
  → 写下一条记录
  → 后台生成有证据的候选认识
  → 用户查看证据并确认、纠正或拒绝
  → 基于已确认认识生成一个可撤销的小行动
  → 用户接受、完成或撤销
  → 回顾结果并保留可追溯历史
```

人生主线、回忆录和日历候选作为黄金路径稳定后的增强闭环，不阻塞首个完整产品版本。真实第三方日历写入、整本回忆录、多人协作和复杂导入继续延后。

## 2. 当前基线

截至 2026-09-01，当前工作树验证结果：

- Ruff、strict mypy 通过；
- 后端 `1059 passed, 2 skipped`；跳过项为需要显式 PostgreSQL DSN 的真实迁移与 RLS 演练；
- Python 覆盖率快照约 79%；
- 桌面端 TypeScript、Vite 生产构建通过；
- Electron 内置服务记录 CRUD 契约通过；
- 已生成 Windows portable 与 NSIS 安装包；
- 完整 FastAPI 已覆盖 Source、Memory、AI 候选、Action、Narrative 与 Calendar Candidate；
- 桌面内置服务仅覆盖记录 CRUD，默认安装体验尚未具备完整 AI 闭环。

完成度基线：

| 维度 | 当前估计 | 本计划目标 |
|---|---:|---:|
| 后端领域与信任边界 | 85% | 95% |
| 默认桌面核心闭环 | 60% | 95% |

| 完整 AI 自我认知产品 | 65% | 85% |

百分比只用于表达相对成熟度；是否完成一律由下文退出条件决定。

## 3. 冻结范围与原则

### 本轮必须完成

- 默认桌面安装后能进入完整黄金路径；
- AI 不可用时仍可可靠记录，且界面明确降级；
- 每个候选认识都有证据、模型运行 lineage 和用户裁定；
- 每个行动必须来自当前有效的已确认/纠正认识，并可撤销；
- 身份、密钥、删除、日志、备份和故障处理达到封闭试点要求；
- 构建、迁移、升级、卸载和数据恢复均有自动化验收。

### 本轮不做

- 诊断、治疗替代或心理评分；
- AI 自动执行日历、Todo、邮件或通知；
- 整本回忆录与 Docx/PDF 专业排版；
- 自动认定唯一人生主线；
- 多设备实时同步、多人协作和微服务拆分；
- 为追求功能覆盖而削弱 fail-closed、RLS、consent 或用户最终裁定权。

## 5. C0：产品契约冻结

### 工作项

1. 建立权威 capability matrix，区分：内置本地、外部完整后端、离线、AI 暂不可用。
2. 冻结黄金路径使用的 API、错误码、幂等键、ETag、任务状态与降级文案。
3. 决定默认发行形态：
   - 推荐：桌面端管理一个受约束的本机完整后端运行时；
   - 备选：桌面端登录托管后端；
   - 不接受：继续让默认内置服务只保存记录、却把完整闭环作为主产品承诺。
4. 为 Source、Candidate、Verdict、Action、Review 定义跨版本兼容契约。
5. 建立需求—API—测试—UI 的追踪表，移除互相矛盾的旧完成度描述。

### 退出条件

- 每个页面只根据服务端 capability 呈现功能；
- UI 不通过示例数据或本机临时状态伪装服务器成功；
- 黄金路径的每一步都有唯一权威 API 和失败语义；
- 架构决策记录明确默认运行形态及其安全边界。

## 6. C1：默认桌面黄金路径

### 工作项

1. 把完整后端运行时纳入桌面发行或接入受控托管后端，统一启动、健康检查和退出。
2. 桌面端接通：
   - 记录创建、修订、删除；
   - 候选生成任务及进度恢复；
   - Memory 详情、证据摘录、确认、纠正、拒绝、暂缓；
   - AI 小行动生成、接受、完成、撤销；
   - 重启后的权威历史恢复。
3. 网络/模型失败时保留草稿与记录能力，不重复 dispatch，不制造假成功。
4. 首次启动完成本地 principal、Vault、consent 和必要密钥材料初始化；升级不得覆盖用户数据。
5. 移除核心路径中的静态示例认识；演示数据必须进入显式 Demo 模式。

### 必测场景

- 首次安装 → 首条记录 → 候选 → 证据 → 确认 → 行动 → 完成 → 重启恢复；
- 候选生成中退出应用，再次启动后恢复任务状态；
- 相同幂等键重放不重复调用模型；
- Source 修订或删除后旧证据默认拒绝；
- consent 撤回后不能继续生成或展示受限正文；
- 模型超时、空响应、结构错误、断网均有可理解且可恢复的状态。

### 退出条件

- 一台未安装 Node、Python、PostgreSQL 的干净 Windows 机器可完成黄金路径；
- 用户不需要手工填写 Vault ID、Bearer Token 或 API 地址；
- 完整路径有自动化 E2E，并在重启边界验证；
- 离线与 AI 故障不会损坏记录或重复产生候选/行动。

## 7. C2：生产信任基础设施

### 工作项

1. 实现 principal/Vault owner 的原子开通、管理员撤销和 membership 生命周期。
2. 接入 KMS/envelope encryption、对象存储和最小权限 ACL；本地 AEAD 只作为开发实现。
3. 为 Source、ModelRun、cursor、command receipt 的 HMAC 引入 key ID/keyring 与轮换窗口。
4. 分离 migration owner、runtime login、worker 和 maintenance 身份。
5. 固化 provider 数据处理策略：地域、留存、训练使用、超时、供应商 request ID 和停用开关。
6. 建立 Secret 注入、轮换和泄漏响应流程，禁止秘密进入前端、日志、回执和构建产物。

### 退出条件

- 在目标 staging 使用非 superuser migration login 与独立 runtime role 完成演练；
- 旧密钥验证、新密钥签发和轮换回滚均有测试；
- 对象版本、AAD、Vault 身份和 ciphertext 完整性验证失败时默认拒绝；
- provider 合同/控制台策略形成有日期、有责任人的审计记录。

## 8. C3：删除、后台任务与故障闭环

### 工作项

1. 实现 durable deletion/outbox worker，覆盖：数据库、对象、检索、向量、派生记忆、叙事、导出和供应商留存请求。
2. 建立最小权限 maintenance repository，处理业务 RLS 下不可见的 tombstone 和删除重试。
3. 完成后台任务 lease、retry、UNKNOWN reconciliation、dead-letter 和人工处理入口。
4. 候选与行动生成统一使用 durable job 模式；同步 API 只负责接受请求和查询状态。
5. 处理上传/加密分段事务中的对象孤儿、数据库回滚和网络不确定性。
6. 实现备份、恢复与备份过期策略，并验证删除在承诺期限内传播。

### 退出条件

- deletion canary 对全部已声明 sink 达到 100% 清除或不可访问；
- 删除失败可重试、可观察、不会静默标记完成；
- worker 崩溃、重复投递和数据库连接中断不产生重复副作用；
- 日志、trace、job payload、dead-letter 不含用户正文；
- 完成一次备份恢复和恢复后删除传播演练。

## 9. C4：产品体验、评测与安全准入

### 工作项

1. 重做认识详情的信息层级：观察、解释、不确定性、支持证据、反例和用户裁定分开展示。
2. 行动页明确“怎么做、为什么、如何退出”，避免将建议表现为命令。
3. 补充键盘操作、焦点管理、缩放、对比度、屏幕阅读器标签和空状态。
4. 建立前端 component/integration/E2E 测试，不只依赖 TypeScript build。
5. 建立中文为主的 adversarial corpus：否定、反讽、转述、混合语言、谐音规避、创伤再呈现和危机表达。
6. 建立模型/prompt/policy 版本化评测与回滚门。
7. 配置首发地区危机资源、知情同意、年龄边界、事件响应负责人和升级流程。

### 发布阻断指标

- 严重无来源事实：0；
- 诊断式或人格定论输出：0；
- 未确认外部副作用：0；
- 删除后正文或证据泄漏：0；
- 跨 Vault 可见：0；
- 核心 E2E、键盘路径和恢复路径通过率：100%。

零观察只表示在已记录样本范围内未发现，不构成真实世界零风险承诺。

## 10. C5：发布工程与封闭试点

### 工作项

1. 建立 CI 发布流水线：lint、mypy、unit、integration、PostgreSQL rehearsal、前端测试、E2E、打包、产物扫描。
2. 对 portable、NSIS、升级、卸载保留数据和崩溃恢复进行干净机测试。
3. 引入 Windows 代码签名、版本策略、数据库兼容窗口和安全回滚。
4. 建立最小可观测性：可用率、任务延迟、provider 失败、RLS denial、删除延迟、stale fence、崩溃率。
5. 建立隐私政策、数据导出/删除入口、供应商清单、支持渠道和安全披露渠道。
6. 先邀请内部/受控封闭用户；禁止直接开放公共注册。

### 退出条件

- CI 从干净 checkout 可重复生成同版本安装包；
- 发布产物经过签名、恶意软件扫描、秘密扫描和 SBOM/依赖清单检查；
- 上一稳定版本可安全升级，失败可回滚且不丢数据；
- 告警、值班责任和用户支持路径真实可用；
- 封闭试点有退出、删除、反馈和严重事件暂停机制。

## 11. C6：人生主线与回忆录增强闭环

C5 稳定后再推进：

1. 人生主线支持逐主题确认、纠正、拒绝、撤销和版本历史；
2. 建立叙事生成快照引用接口，避免无关 Source 写入导致旧引用不可读；
3. 单章回忆录支持逐段事实/反思/文学连接标记与编辑；
4. 删除或排除材料后，受影响章节标记过期并允许重建；
5. 日历候选继续保持本地确认与 ICS 导出，不把确认描述成已写入第三方；
6. 真实 Calendar OAuth/远端写入单独立项，必须复用 single-use authorization 与 UNKNOWN 对账。

### 退出条件

- 每条主题和事实性叙述可回到生成时已验证材料；
- 用户能逐主题裁定，而不是只能接受整代 generation；
- 材料空白不会被模型补写成事实；
- 回忆录内容永不反向成为 Life Model 的事实证据。

## 12. 建议执行批次

### 批次 A：先完成默认闭环

- C0 capability/API 冻结；
- C1 后端运行形态决策与桌面接线；
- 黄金路径 Playwright/Electron E2E；
- 删除静态示例数据对真实状态的干扰。

### 批次 B：补生产底座

- C2 身份开通、KMS/object store、keyring；
- C3 deletion worker、durable AI jobs、恢复演练；
- 目标 PostgreSQL staging trust-boundary 测试。

### 批次 C：发布准入

- C4 UX、安全语料与无障碍；
- C5 CI、签名、升级、监控和封闭试点；
- 试点稳定后进入 C6。

任何批次不得以未提交、不可复现的人工 canary 代替自动化退出门。

## 13. 总完成定义

项目只有同时满足以下条件，才能称为“核心产品完成”：

1. 普通用户从安装到完成黄金路径无需开发环境或手工配置；
2. 原始记录在 AI 离线时仍可创建、修订、导出和删除；
3. 所有 AI 认识可追溯、可质疑、可纠正、可拒绝、可撤销；
4. 所有行动由用户主动选择，且接受后仍可完成或撤销；
5. consent、Source、membership 或 fence 失效时默认拒绝；
6. 跨 Vault、删除残留、日志正文泄漏和越权副作用的阻断测试全部通过；
7. 真实 PostgreSQL、KMS/object store、provider、备份恢复和密钥轮换均有 staging 演练；
8. Windows 安装、升级、卸载、重启和断网恢复均通过自动化或可重复验收；
9. 产品有监控、暂停发布、事件响应、用户退出和数据删除能力；
10. README、能力发现、界面文案和实际运行状态一致。

满足上述条件后，项目可定义为“封闭试点可用的完整核心产品”；公共发布仍需根据试点数据单独做安全、隐私和运营评审。
