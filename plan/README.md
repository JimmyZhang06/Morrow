# 自我认知 Life Coach：后端实现计划

> 状态：架构基线 v0.1  
> 调研日期：2026-08-23  
> 目标阶段：从 0 到可验证 MVP；不是最终技术规格

## 1. 一句话结论

这个产品的后端不应是“一个会记住一切的聊天机器人”，而应是一个**由用户校订、可追溯、可撤回的个人生命模型**：原始记录是唯一可追溯的材料源（不等于对客观历史的证明），AI 只生成带证据的候选解释；洞察、行动建议和回忆录都由这些可验证材料生成。

首版采用：

```text
模块化单体 API + 异步 Worker
+ PostgreSQL（结构化数据、全文检索、事务）
+ pgvector（可重建的语义索引）
+ 对象存储（音频、图片、导入文件）
+ 可替换模型网关
```

暂不采用微服务、独立图数据库、CRDT、Temporal，也不把 Letta、Mem0、Graphiti 中任何一个直接作为主事实库。Graphiti 与 Mem0 进入隔离 PoC；验证收益后再接入。

## 2. 这套架构保护的五件事

1. **原话优先**：用户写下或说出的内容不可被 AI 静默改写。
2. **推断有出处**：每个“你可能……”都能回到具体原文，并同时保留反证。
3. **身份由用户决定**：价值观、人格、关系模式、人生主线只能是待确认假设，不能被模型擅自固化。
4. **建议不等于命令**：系统先产生行动候选；只有用户接受后才成为任务，外部副作用需再次授权。
5. **遗忘真实有效**：删除必须从检索、派生记忆、向量、图投影、文稿和模型上下文中级联生效。

## 3. MVP 的产品闭环

```text
低摩擦记录
  → 后台理解但不打扰
  → 有证据的“我注意到……”
  → 用户确认 / 修正 / 驳回
  → 用户自选一个小实验或行动
  → 事后回顾结果
  → 更新生命模型与人生手稿
```

北极星不是记录量、聊天时长或 AI 生成字数，而是：

> 被用户确认的洞察，是否帮助其选择并完成了一个符合自身价值的小行动，并在之后形成了可回顾的结果。

## 5. 已做出的关键决策

| 议题 | 决策 | 何时重审 |
|---|---|---|
| 系统记录主库 | 自研 PostgreSQL 领域模型 | 不重审；属于产品信任根基 |
| 架构形态 | 模块化单体 + Worker | 团队或独立扩缩需求明显时 |
| 检索 | PostgreSQL FTS + pgvector + 结构化过滤 | 数据量和评测证明需要图检索时 |
| 图数据库 | MVP 不引入；Graphiti 做影子 PoC | 多跳主题召回显著优于基线时 |
| 异步编排 | `jobs + outbox` | 出现复杂等待、限流、重试风暴后评估 Hatchet |
| 长期记忆 | 候选—确认—争议—撤回的版本链 | 不允许退化为自动覆盖文本 |
| 端到端加密 | 明确区分“云端可检索”与“真正 E2EE” | 客户端计算/本地模型可行时 |
| 心理定位 | 自我反思与行为支持，不做诊断/治疗替代 | 不重审；合规与伦理边界 |

## 6. MVP 明确不做

- 不自动诊断抑郁、焦虑、人格类型、依恋类型等临床或准临床标签。
- 不把一次情绪表达升级成稳定人格结论。
- 不自动联系亲友、医生、警方或任何第三方。
- 不自动创建日历、发送消息、花钱或公开内容。
- 不用“连续签到、人生分数、红色预警”制造羞耻和依赖。
- 不承诺真正 E2EE 后又把明文或可逆内容交给云端模型处理。
- 不让生成的回忆录反向成为用户人生事实的证据。

## 7. 建议的代码边界

即使首版是单仓单服务，也应按业务模块隔离：

```text
apps/
  api/
  worker/
modules/
  identity/       # 账号、设备、会话、租户
  consent/        # 同意、数据策略、功能开关
  sources/        # 原始记录、附件、导入、修订
  knowledge/      # 片段、证据、记忆、人物、事件、关系
  retrieval/      # FTS、向量、重排、上下文包
  reflection/     # 洞察与问句
  action/         # 候选行动、小实验、复盘
  narrative/      # 时间线、章节、回忆录草稿
  safety/         # 输入/输出风险检查与安全交接
  privacy/        # 导出、删除、保留、审计
  model_gateway/  # 模型路由、结构化输出、成本与隐私策略
platform/
  db/
  jobs/
  object_store/
  observability/
```

模块之间通过应用服务接口和领域事件协作，不能跨模块直接写表。这样既保留 MVP 的简单部署，也为未来拆分提供真实边界。
