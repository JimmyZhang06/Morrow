# Morrow：逐轮自动检索与对话分析改进

日期：2026-09-11。承接 33 号实现文档；本批覆盖其“每轮自动扩大材料范围尚未实现”的旧限制。

## 用户体验

- 新建对话默认勾选自动查找，用户仍需确认在线模型发送授权。手动查找与选日记作为可选展开区保留。
- 每次发送问题自动执行本地关键词检索，无需先点查找按钮。输入区可关闭自动查找；重新打开已有会话时默认关闭，防止静默扩大历史会话范围。
- 自动查找需要记录页已经开启 SEARCH 并建立本地索引。没有索引或没有命中时不编造经历，回答旁提示覆盖情况。
- 原文引用折叠为一个“参考来源 · N 篇”入口，同篇日记合并、相同原话去重。需要核对时再展开并跳转原文。
- 顶部标注手动选定的材料；每条回答单独显示自动检索数量，不把两种范围混淆。

## 后端与授权

`POST /v1/conversations/{id}/turns` 新增 `auto_retrieve`，默认 false。旧调用与旧会话维持固定范围。幂等校验同时核对问题和是否自动检索。

入队事务中执行 `search_diaries`，保留其当前 Vault、当前原文修订、SEARCH 授权、敏感级别与完整性检查。检索后逐条检查 PASSIVE_QA 和 CROSS_RECORD_ANALYSIS，再加入本轮上下文。手动材料优先，每轮合计最多 8 个日记片段，自动补入材料受 14000 字符预算限制；最终仍受模型网关总上下文预算限制。

当前检索是本地关键词匹配，不是向量语义检索。最多扫描最近 1000 个日记片段，从前 50 个匹配结果内选取允许使用的材料。短追问含“继续、为什么、那我、这件事、刚才、怎么办”时，追加上一条用户问题帮助召回；这只是有界规则，不是完整的对话意图解析。

Alembic `45de67fa89bc` 新增 `conversation_turn.retrieval JSON`。只保存片段 ID、自动补入片段 ID、覆盖统计及检索模式，不保存问题、日记原文或搜索词明文。旧轮次为 NULL；兼容前置迁移以当前模型注册表建表的空库路径。

每轮材料在入队时固定。准备、派发、提交仍使用既有授权与来源版本校验，自动材料额外复查 SEARCH。历史回答按其各自材料和认识版本验证；材料变化后不把旧 assistant 回答作为新一轮依据，保留用户提问以支持追问。自动来源的删除或编辑也进入会话答案清理范围。

## 分析改进

对话模板更新为 `conversation-reply-v3`，提供本轮材料范围和日记记录时间。要求模型先回答实际问题，再解释具体依据、反例或替代解释，最后至多提出一个有用的追问或小尝试。简单闲聊不强制套分析模板。

已确认认识仍是用户认可的解释，不是客观事实；优先当前纠正版本。单次事件不能推成稳定人格或因果规律。材料不足时问缺失的具体信息，不用泛泛鼓励填补。只请求 1–3 条最有解释价值的原话；后端继续逐条验证引用身份与原文一致性，前端合并来源。

这批优化的是可验证的上下文和回答要求，不能把合成模型测试当成真实分析质量评测。真实模型应以以下场景比较新旧模板：

| 场景 | 合格回答的具体要求 |
| --- | --- |
| 散步后完成任务，但另一天散步后仍拖延 | 同时讨论两条经历，不能直接声称散步导致高效率 |
| 用户纠正“内向”为“陌生场合需准备” | 使用当前范围，不能重新贴稳定人格标签 |
| 从工作压力换到睡眠问题 | 新检索进入睡眠材料，不沿用旧工作结论作证据 |
| 用户追问“为什么” | 结合上一问题并说明可能解释，不假装知道真实原因 |
| 日记里没有相关信息 | 明确资料不足，提出一个具体问题 |
| 仅一篇相关日记 | 不声称长期趋势或重复模式 |
| 出现大量相似日记 | 回答集中于有区分度的经历，来源列表不堆叠 |
| 日记已撤权或高度敏感 | 不进入模型上下文，也不能保留旧回答作替代依据 |

评测时比较具体性、证据忠实度、反例处理、纠正遵循和下一步可操作性。尚未调用用户真实模型或真实日记进行评分，不报告虚构分数。

## 验证

完整后端测试通过（1131 项通过、2 项跳过）；Ruff、严格 mypy 和 TypeScript/Vite 构建通过。实际 Electron 使用独立临时数据、真实 PostgreSQL 和合成 HTTP 模型验证：不手选日记直接提问命中、来源默认折叠、展开查看原文、纠正传播，以及原有聊天流程。界面截图位于 `.data/release-evidence/conversations/`。

本地构建目录为 `apps/desktop/release-chat-auto/win-unpacked`，没有发布新安装器或 GitHub Release，不清除用户已有数据。

打包后端与真实 PostgreSQL 的升级、降级再升级、RLS、备份恢复和重启验证通过。最新 Electron 构建的独立空白配置启动通过：无记录、认识、行动、会话、草稿和模型密钥，AI 默认关闭。
