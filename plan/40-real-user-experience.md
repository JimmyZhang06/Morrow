# Morrow 真实用户体验报告

日期：2026-09-11 · 体验版本：0.6.0-beta.6（visual-refresh 打包版）

## 结论

软件的核心路径已经能走通：记录生活、与 AI 聊天、生成并确认认识、设计小尝试、整理主线、生成回忆录、阅读回信和关怀来信。但是，当前还不适合把“顺畅、可靠地记住我”作为已完成的体验承诺。

最需要优先解决的是：AI 调用结果不稳定；后台生成与正常聊天互相干扰；部分认识突然失去可用依据；日记关怀触发条件与首页默认记录类型不匹配；确认后的认识缺少再次纠正入口；关闭 AI 后看不到已有叙事。

本轮只体验、取证和记录，没有修改产品功能，也没有修改你的真实日记。所有写入、删除、恢复都发生在独立测试档案中。

## 本次如何体验

- 使用真实 Windows 打包程序 `apps/desktop/release-visual-refresh/win-unpacked/Morrow.exe`，真实本地 PostgreSQL 和生产后端。
- 使用当前已配置的 `deepseek-v4-flash-vision-exp`，兼容协议、JSON 模式；实际调用 `api.deepseek.com`。没有使用固定回答、测试模型或伪造的认识来补齐流程。
- 创建独立空数据库，只复用本机受保护的模型配置；没有复制你的真实生活记录。测试结束时，独立档案的 AI 已关闭，密钥已清除。
- 主要通过界面点击、输入、快捷键和重启操作；通过本地 API 与只读数据库回执核对状态、引用、时间和恢复结果。备份对话框由测试程序选择测试文件路径；加密和恢复仍走真实产品流程。日历 ICS 检查使用产品 API，未导入外部日历。
- 测试人物是虚构的“林舟”：准备梧桐项目原型，担心评价，发现十分钟草稿有助于启动，喜欢散步。聊天中把截止时间从周五更正为下周二，再加入压力、疲惫和希望被理解的场景。
- 桌面截图的设备像素比为 2；另外检查了约 979×700 的逻辑窗口。六个主页面均未出现文档级横向溢出。
- 本次是覆盖全部主功能的探索体验，不是对所有异常分支、所有模型及长时间使用的穷尽测试。测试材料带有“体验测试”标记，模型有时会提及这一点；纯聊天关怀场景没有这个前缀。

## 优先问题清单

P1 表示影响主要使用路径或用户控制权；P2 表示明显影响理解与体验；P3 表示内容和排版改进。以下建议尚未实施。

### F01 · P1 · 正常聊天会打断后台认识生成

**复现：** 从记录点击“发现一个线索”，界面提示可以继续做别的事；随后进入已有对话并发送一条消息。首次和一次重试均出现 `authorization.changed_after_dispatch`，认识没有保存。单独生成、期间不发送聊天时成功。

**预期：** 不涉及原文或其授权的正常聊天，不应让另一项已授权任务无效。真正撤回材料权限时仍应安全停止。

**实际影响：** 用户按提示继续使用软件，却损失生成结果，并可能承担已发生的调用费用。

**建议：** 检查授权/来源版本的失效范围，区分当前任务所依赖的材料与无关新增内容。不要简单取消授权复核。证据：调用回执第 2、5 条，以及 [失败页面](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/08-insight-failure.png>)。

### F02 · P1 · 成功生成的认识打开时没有可用依据

“安静周末”的认识已经生成成功；之后进行正常聊天，再打开该认识，支持和反例都为 0，页面要求重新整理。该日记没有被修改或删除。原始 API 返回 `authorization_snapshot: null`、空依据和空 allowed_uses。

这会阻断确认、纠正及后续行动。生成成功后的依据为什么不可用仍需定位；本次记录到了发生顺序，不把“后续聊天”直接认定为唯一根因。

证据：[认识详情](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/memory-detail.json>)、[页面](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/16-memory-review.png>)。建议保留可解释的失效原因和回到原文的入口，避免让用户反复调用模型却无法裁定。

### F03 · P1 · 日记关怀筛选与默认记录类型不匹配

20:19:26 开启关怀，随后从首页保存一条明确疲惫、沮丧的新记录。20:29:28 后台检查时间已更新，没有生成日记关怀任务。只读查询显示当时 4 条日记全部为 sensitive。

实现核对：日记检查只选 `DataClass.NORMAL`；聊天只要带有 sensitive 日记，也不允许附带关怀信。因此普通用户通过现有首页路径写的日记，无法进入这条关怀通道。设置中的“普通日记”也没有说明与“敏感 · 私密”的对应关系。

建议设计清楚的“允许用于关怀”范围和授权交互，统一 UI 与后端规则；不要为触发来信而偷偷降低记录的敏感级别。

证据：[检查时间](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/result-30.json>)、[记录类型统计](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/result-31.json>)；实现位置：[care_letters.py](<C:/Users/Zhang/Desktop/开发项目/自我认知/src/life_coach/application/care_letters.py:240>)。

### F04 · P1 · 确认后的认识没有再次纠正入口

点击“符合我的感受”后，按钮区消失，只剩认可提示和创建尝试入口。首次点击“不完全是”可以成功纠正，但确认/纠正后的再次编辑同样没有入口。界面仍写着“可随时修改”“之后仍可修改”。

建议给已裁定认识持续提供“修改理解、改变判断、撤回”等明确操作，并展示改动影响。证据：[已纠正页面](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/46-corrected.png>)、[确认后的界面文本](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/result-19.json>)。

### F05 · P1 · 真实 AI 调用稳定性不足，失败解释无法帮助用户恢复

20 次实际调用中 6 次 unknown，涉及安慰聊天、回信、回忆录和重启后续聊。用户看到“核对模型侧记录”或“检查账户及网络”，却没有足够的可操作信息。回忆录失败后，页面最终仍像未生成过一样，只显示空章节。

不自动重发是合理的；问题在于失败结果缺少持久、可理解的任务记录。建议区分连接失败、供应商拒绝、输出不合要求、已取消和授权变化；提供保留输入的显式重试操作。当前回执不足以把这 6 次全部归为某一种原因。

### F06 · P1 · 关闭 AI 后，已有主线、回忆录和日历无法查看

正确恢复备份会关闭 AI。随后访问主线，只出现“叙事生成尚未开启”；日历列表 API 返回 404。只读数据库检查仍有 2 条 narrative_generation 和 1 条 calendar_candidate，因此不是恢复删除了数据。

建议将“允许新生成”与“读取本地已有结果”分开。停用模型、余额不足或恢复备份，都不应让已生成的生活内容失去入口。

证据：[关闭 AI 后页面](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/56-ai-off-narrative.png>)、[数据库计数](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/restored-hidden-data.csv>)。

### F07 · P2 · 记忆只在部分功能内连续

同一聊天正确记住“下周二”；随后生成的小尝试却说“不会影响周五给同事看原型的计划”，采用了旧日记中的日期。

现有会话历史设计明确限定同一会话，没有承诺跨会话画像。因此这里应区分：短会话记忆测试通过，但整个软件距离用户期待的统一记忆仍有差距。建议记录有出处、可撤回的事实纠正，并在不同功能用到冲突事实时主动核对，避免悄悄沿用旧版本。

证据：[聊天纠正与回忆](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/chat-memory.json>)、[小尝试原始输出](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/actions-generated.json>)。

### F08 · P2 · 聊天引用被当成日记，时间显示错误

在首个会话展开参考来源，点击更正消息的“查看原文 1”，打开的是“记录详情”，显示“1 月 1 日周四 08:00”，正文实际是刚才的聊天消息，还提供“创建修订、删除、发现一个线索”。

建议引用按来源类型显示“本次聊天中的第几条消息”，正确使用消息时间，点击后定位消息。证据：[错误来源页面](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/43-conversation-source.png>)。

### F09 · P2 · 记录状态长期互相矛盾

未请求整理的记录显示“正在整理”；已成功生成认识的记录仍显示“后台整理：正在整理”；失败记录同时显示“整理未完成 100%”与“正在整理”。

建议统一状态来源，区分已保存、未开始分析、排队、生成中、完成和失败。100% 不应让失败看起来像完成。证据：[失败状态](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/08-insight-failure.png>)、[已生成但仍整理中](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/43-letter-source.png>)。

### F10 · P2 · 隐私遮罩没有覆盖最近记录

开启遮罩后主内容模糊，但侧栏“最近记录”的开头仍可读。虽然设置说明只说主内容区域，实际旁人仍可能看到敏感内容。

建议同步隐藏日记摘要、聊天标题等内容性文字，保留导航名称即可。证据：[隐私遮罩截图](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/48-privacy.png>)。

### F11 · P2 · 回复格式与用户的长度要求不一致

模型输出 `**梧桐项目**`、`**周五**`，界面直接展示星号，没有渲染强调。请求“一句话”仍收到正文加长段附注；请求约 100 字回信，最终是一篇数百字回答，包含“我把它写成一封短信”的二次引入。

建议统一模型输出与展示格式，在正文安全渲染支持的格式，或约束模型输出纯文本；将需要展开的依据说明收起。回信模式应直接生成信正文，避免“信纸中的聊天回答里又嵌一封信”。证据：[聊天格式](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/03-chat-result.png>)、[实际回信](<C:/Users/Zhang/Desktop/开发项目/自我认知/.data/real-user-audit/42-letter-readable.png>)。

### F12 · P3 · 叙事和行动的文案过于像分析报告

主线出现“可 tentative 理解为”的中英混用，以及“反例认识 M1”“关联认识 M1”。回忆录大量篇幅重复说明材料不足，更像审阅说明；行动卡把做法和理由接成一个大段，信息重复。

建议将证据解释与主要内容分层呈现；保持事实谨慎，同时让回忆录像用户能阅读的一段经历。材料确实只有一条，不应为了文采补写虚构人生。

## AI 内容中符合预期的部分

- 事实回忆明确采用最新更正：“截止时间以你后来的更正为准：下周二”，并保留散步与社交偏好。
- 认识会使用“可能”“一次体验”等表达，并引用实际原话，没有把候选自动当成确定人格。
- 安慰场景尊重“不想听建议”，没有直接推销一大串任务。关怀信写道：“今晚不用说什么，我在这里陪你安静待着。”正文没有诊断，也没有要求用户必须回应。
- 小尝试有十分钟时限和退出办法，需用户接受才开始，完成和撤销均有状态记录。
- 主线提供另一种解释和材料空白，没有根据一条记录虚构多年经历。
- 回信能连接过去的十分钟草稿经验与当前疲惫，原文引用可以回到真实日记。信封、打开过程和阅读在同一个弹窗内完成，本次未看到页面分离；没有用前次的测试模型截图冒充本次结果。

## 备份恢复及测试边界

导出加密备份约 700 KB。错误密码返回明确错误，现有记录不变。正确恢复后，4 条日记、4 个会话、3 条认识、1 个尝试的 API 内容与备份前一致。日历接口因 AI 关闭返回 404，不能将它写成 API 恢复通过；数据库计数证明其记录仍在。后续在独立测试档案内又执行了聊天删除和尝试撤销，因此最终档案数量可以与这个恢复检查点不同。
